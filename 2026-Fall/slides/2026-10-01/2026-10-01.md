# Responsive Design

Making one site work on every screen

## Why this matters

- Roughly **70% of web traffic is mobile**
- Your users are on phones, tablets, laptops, desktops, TVs
- You cannot build a separate site for each one
- **One site. Every screen.**

---

## You already have step one

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0" />
```

This has been in our boilerplate since week one.

Without it, phones pretend to be a 980px-wide desktop and shrink everything.

---

## Fixed vs fluid widths

```css
/* Fixed - breaks on small screens */
.card {
  width: 600px;
}

/* Fluid - adapts */
.card {
  width: 100%;
  max-width: 600px;
}
```

**Rule of thumb:** use `max-width` instead of `width` almost every time.

---

## Responsive images

One line fixes the most common beginner bug:

```css
img {
  max-width: 100%;
  height: auto;
}
```

Now images shrink to fit their container instead of blowing out the layout.

## Media queries

A media query says: "when the screen is this size, use these rules instead."

```css
/* Applies at ALL sizes */
.container {
  padding: 1rem;
}

/* Applies only when screen is 768px or wider */
@media (min-width: 768px) {
  .container {
    padding: 3rem;
  }
}
```

---

## Anatomy of a media query

```css
@media (min-width: 768px) {
  /* rules go here */
}
```

- `@media` — this is a media query
- `(min-width: 768px)` — the condition
- `{ }` — the rules that apply when the condition is true

---

## min-width vs max-width

```css
/* Screen is AT LEAST 768px - "this size or bigger" */
@media (min-width: 768px) { }

/* Screen is AT MOST 767px - "this size or smaller" */
@media (max-width: 767px) { }
```

We will use **`min-width`**. Here's why...

## Mobile-first

Two ways to build:

- **Desktop-first** — design big, then patch it for small screens
- **Mobile-first** — design small, then add complexity for big screens

Mobile-first wins because:

- Small screens force you to decide what actually matters
- Phones are the majority of your traffic
- Your base CSS stays simple

---

## Mobile-first in practice

```css
/* Base styles = mobile. No media query needed. */
.cards {
  display: flex;
  flex-direction: column;
  gap: 1rem;
}

/* Tablet and up: switch to a row */
@media (min-width: 768px) {
  .cards {
    flex-direction: row;
  }
}
```

Write for the phone first. Add media queries to *upgrade*.

---

## Common breakpoints

There are no official breakpoints. These are conventional:

| Width | Roughly |
|---|---|
| `480px` | Large phone |
| `768px` | Tablet |
| `1024px` | Laptop |
| `1280px` | Desktop |

**Better advice:** add a breakpoint where *your* layout starts looking bad, not where a chart says to.

---

## Remember this from last week?

```css
.gallery {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(200px, 1fr));
  gap: 1rem;
}
```

This is responsive with **zero media queries**.

Modern CSS often lets you avoid breakpoints entirely. Reach for media queries when layout needs to actually *change*, not just resize.

## Testing without a phone

Chrome / Edge / Firefox DevTools:

- Open DevTools (`Ctrl + Shift + C` / `Cmd + Option + C`)
- Click the **device toolbar** icon (phone + tablet symbol)
- Pick a device, or drag the edges to any size
- Watch your media queries kick in live

---

## Things that break on mobile

- Fixed pixel widths
- Images without `max-width: 100%`
- Text too small to read (don't go below `16px` body text)
- Buttons/links too small to tap — aim for about `44px` of tappable area
- Horizontal scrolling (almost always a fixed-width element)
- Hover-only interactions — **there is no hover on a phone**
